# Queens 생성 실험

`/queens`는 5×5~9×9 크기를 선택해 LLM이 디자인한 퍼즐을 생성·검증하고 그 자리에서 바로 플레이하는 화면이다.

## 규칙과 데이터

[LinkedIn Queens 규칙](https://www.linkedin.com/help/linkedin/answer/a6269510): 각 행·열·색상 영역에 퀸을 하나씩 배치하고, 대각선을 포함한 인접 칸에는 두 퀸을 놓지 않는다. 멀리 떨어진 대각선은 허용한다.

퍼즐은 `{ size: N, regions: RegionId[][] }`, 정답은 `{ row, column }[]`로 표현한다. 좌표는 0부터 시작한다. 영역 ID는 문자열 또는 0 이상의 정수다. 검증 알고리즘은 최대 12×12 격자를 지원한다.

- 격자가 N×N인지, 영역이 정확히 N개인지 확인한다.
- 영역마다 상하좌우 flood fill로 연결성을 확인한다.
- 퀸 배치의 개수·좌표·행·열·영역·인접 충돌을 검사한다.
- 백트래킹으로 두 번째 정답까지 탐색한다. `multiple` 오류에는 서로 다른 두 배치가 메시지와 구조화된 데이터에 모두 포함된다.
- 기본 100,000개 후보 검사 한도에 도달하면 `inconclusive`를 반환한다. 해가 하나 발견됐더라도 탐색이 끝나지 않았으면 유일하다고 판정하지 않는다.

## 생성과 도구

채팅 에이전트에는 `verify_puzzle`, `validate_queens_placement` 도구를 그대로 유지한다.

퍼즐 생성은 탐색(코드)·다양성(난수)·영역 디자인(추론 모드 LLM)을 분리한다.

1. **정답 배치 생성(코드)**: 행마다 후보 열 순서를 무작위로 섞은 백트래킹으로 유효한 퀸 배치를 만든다.
2. **영역 디자인(LLM)**: 생성된 정답 퀸 배치가 주어지면, 그 배치가 유일한 정답이 되도록 N×N 격자를 N개의 연결된 색상 영역으로 나누는 JSON을 출력한다. 편법을 막기 위해 각 영역은 최소 2칸 이상이어야 한다.
3. **직접 검증·보정(코드)**: 도구 호출 없이 `validateDesign`으로 검증한다. 모델은 1회(20초, reasoning 없음)만 영역 모양을 제안하고, 코드가 끊어진 조각과 작은 영역(2칸 영역은 최대 1개)을 보정해 완성한다. 실패하면 모델 시드 재성장(재시작 100·solver 2,000) → 순수 알고리즘(재시작 500·solver 4,000) 순으로 넘어가며 모델을 다시 호출하지 않는다. 결과 경로는 `model`·`model-seed`·`algorithm`이다. API 오류·취소는 재시도하지 않는다.

다양성은 코드의 무작위 배치가 담당하므로 LLM 호출에는 `temperature`와 `reasoning_effort`를 지정하지 않고 모델 기본 추론 모드를 사용해 제약 준수 정확성에 집중한다.

`POST /api/queens/generate`에 `{ "size": 5 }`를 전달하면 NDJSON으로 시도·정답 배치(`placement`)·영역 디자인 제안(`candidate`)·검증 결과·피드백을 스트리밍한다. 성공은 `result`, 오류는 Problem Details를 담은 `problem` 프레임으로 종료한다. 진행 순서는 Pino 로그와 화면 진행 기록에서 확인할 수 있다.

`pnpm test`로 알고리즘, 단일/복수/해 없음, 예산 소진·취소, 에이전트 도구, HTTP 스트림을 검증한다.

## 플레이

퍼즐 생성이 완료되면 별도 화면 이동 없이 `/queens` 화면에서 바로 플레이할 수 있다.

- **칸 클릭 순환**: 각 칸을 클릭할 때마다 빈칸 → X 표시(`cross`) → 퀸(`queen`) → 빈칸 순으로 상태가 순환한다.
- **이동 수 표시**: 칸을 바꿀 때마다 이동 수가 1씩 증가해 화면에 `이동 N회`로 표시되며, `다시 하기`를 누르면 0으로 초기화된다.
- **충돌 강조**: 배치된 퀸 중 같은 행·열·색상 영역에 있거나 대각선을 포함한 인접 칸에 다른 퀸이 있으면 충돌 칸으로 강조 표시한다.
- **완성 판정**: 배치된 퀸이 정확히 N개이고 충돌이 없으면 퍼즐이 완성된다.
- **다시 하기·정답 보기**: `다시 하기`로 보드와 이동 횟수를 초기화하거나, `정답 보기`로 생성된 정답 배치를 바로 표시할 수 있다. 완성되거나 정답을 본 뒤에는 보드 칸이 비활성화되어 추가 클릭이 무시된다.

레이어별 역할은 다음과 같다.
- `src/domain/queens/play.ts`: 보드 생성(`createPlayBoard`), 불변 마크 순환(`cycleMark`), 충돌 판정(`findConflicts`), 완성 판정(`isSolved`) 등 순수 규칙
- `src/app/queens/play-store.ts`: 보드 상태·이동 횟수·완성/정답 공개 여부와 구독을 관리하는 플레이 컨트롤러(`createPlayController`)
- `src/ui/components/queens/QueensBoard.tsx`, `src/ui/widgets/queens/QueensGeneratorWidget.tsx`: 퍼즐 격자 렌더링, 클릭/충돌/완성 표시, 다시 하기·정답 보기 UI
