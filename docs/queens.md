# Queens 생성 실험

`/queen`은 5×5~9×9 크기를 선택해 LLM이 직접 제안한 퍼즐을 검증하는 화면이다. 게임 플레이·퀸 배치 편집 UI는 포함하지 않는다.

## 규칙과 데이터

[LinkedIn Queens 규칙](https://www.linkedin.com/help/linkedin/answer/a6269510): 각 행·열·색상 영역에 퀸을 하나씩 배치하고, 대각선을 포함한 인접 칸에는 두 퀸을 놓지 않는다. 멀리 떨어진 대각선은 허용한다.

퍼즐은 `{ size: N, regions: RegionId[][] }`, 정답은 `{ row, column }[]`로 표현한다. 좌표는 0부터 시작한다. 영역 ID는 문자열 또는 0 이상의 정수다. 검증 알고리즘은 최대 12×12 격자를 지원한다.

- 격자가 N×N인지, 영역이 정확히 N개인지 확인한다.
- 영역마다 상하좌우 flood fill로 연결성을 확인한다.
- 퀸 배치의 개수·좌표·행·열·영역·인접 충돌을 검사한다.
- 백트래킹으로 두 번째 정답까지 탐색한다. `multiple` 오류에는 서로 다른 두 배치가 메시지와 구조화된 데이터에 모두 포함된다.
- 기본 100,000개 후보 검사 한도에 도달하면 `inconclusive`를 반환한다. 해가 하나 발견됐더라도 탐색이 끝나지 않았으면 유일하다고 판정하지 않는다.

## 생성과 도구

채팅 에이전트에는 `verify_puzzle`, `validate_queens_placement` 도구를 그대로 유지한다.

퍼즐 생성은 탐색(코드)·다양성(난수)·영역 디자인(추론 모드 LLM)을 분리한다.

1. **정답 배치 생성(코드)**: 행마다 후보 열 순서를 무작위로 섞은 백트래킹으로 유효한 퀸 배치를 만든다.
2. **영역 디자인(LLM)**: 생성된 정답 퀸 배치가 주어지면, 그 배치가 유일한 정답이 되도록 N×N 격자를 N개의 연결된 색상 영역으로 나누는 JSON을 출력한다. 편법을 막기 위해 각 영역은 최소 2칸 이상이어야 한다.
3. **직접 검증 및 피드백 재시도(코드)**: 생성 과정에서는 도구 호출 없이 코드가 `validateDesign`을 직접 호출해 검증한다. 실패 시 오류 피드백을 다음 시도에 전달하며 최초 생성 후 최대 10회 재시도한다(모델 호출 최대 11회). 유효하고 정답이 유일한 퍼즐을 찾으면 즉시 종료하며, API 오류나 취소는 재시도하지 않고 종료한다.

다양성은 코드의 무작위 배치가 담당하므로 LLM 호출에는 `temperature`와 `reasoning_effort`를 지정하지 않고 모델 기본 추론 모드를 사용해 제약 준수 정확성에 집중한다.

`POST /api/queen/generate`에 `{ "size": 5 }`를 전달하면 NDJSON으로 시도·정답 배치(`placement`)·영역 디자인 제안(`candidate`)·검증 결과·피드백을 스트리밍한다. 성공은 `result`, 오류는 Problem Details를 담은 `problem` 프레임으로 종료한다. 진행 순서는 Pino 로그와 화면 진행 기록에서 확인할 수 있다.

`pnpm test`로 알고리즘, 단일/복수/해 없음, 재시도·취소, 에이전트 도구, HTTP 스트림을 검증한다.
