## 운영 구성
- 총괄은 `ps-opus`이고 워커는 `ps-grok`, `ps-ds`, `ps-hd`, `ps-hf`이다. Herdr 라벨 접두어는 `ps-`이며 hydro는 `hd`로 부른다.
- 작업마다 흐름을 같게 했다. opus가 실패하는 테스트나 인터페이스를 먼저 정하고, 파일 단위로 겹치지 않게 워커에 분배했다. 워커마다 watcher를 1개씩 붙였다. 이어서 구현에 참여하지 않은 워커(ps-hf)가 교차 리뷰를 하고, `work-reviewer`가 최종 판정을 내렸다. 그 뒤 opus가 스크린샷을 직접 확인하고 커밋·태그했다.
- 4.1.0에서는 교차 리뷰 지적 7건 중 5건을 반영했고, 4.2.0에서는 5건을 모두 반영했다. 최종 판정은 두 번 모두 PASS였다.

## 잘된 점
- **테스트와 인터페이스를 먼저 정한 분배.** 같은 작업 트리에서 워커 3명이 동시에 작업했지만 파일 충돌이 없었다. 의존 대상이 아직 없어 생긴 typecheck 실패는 일시적이었고, 의존 대상이 완성되자 해소됐다.
- **교차 리뷰에서 실제 결함을 잡았다.**
  - JSON 파싱에 실패하면 `candidate.regions`가 `undefined`가 되어 NDJSON 직렬화에서 사라졌다.
  - 모델 호출 도중 취소하면 영문 원문 오류가 그대로 노출됐다.
  - 호버 규칙의 명시도가 더 높아 충돌 칸의 빨간 강조가 가려졌다.
  - 옛 Queens 기준(temperature 0.8)을 단정하는 레거시 테스트가 남아 있었다.
- **화면 확인을 두 번 했다.** 첫 스크린샷에는 퀸 2개만 놓인 상태만 담겨 있었다. X, 충돌, 완성, 정답 공개 상태를 추가로 요청해 opus가 직접 확인했다.

| 8 | opencode의 `--model` 옵션이 없음(2.3.0) | CLI가 지원하지 않음 | 실행한 뒤 `/models`에서 선택. `ps-ds`는 OpenCode Go 항목을 골라야 함(Ollama Cloud와 이름이 같음) |

## 남은 과제
- **실제 생성 시간을 측정하지 못했다.** 추론 모드로 최대 11회 호출하면 클라이언트 제한 시간 300초(`http-queens-generator.ts`)를 넘길 수 있다. 실제로 측정한 뒤 제한 시간이나 재시도 횟수를 조정한다.
- **UI 렌더 테스트가 없다.** `node --test`가 `.tsx`를 실행하지 못한다. 그래서 칸 표시 결정만 `cell-view.ts` 순수 함수로 분리해 테스트했다. 컴포넌트까지 테스트하려면 Solid JSX 변환을 지원하는 테스트 실행기가 필요하다.
- **9×9 화면은 계산으로만 확인했다.** 390px 폭에서 실제 렌더를 촬영하지 않았다.
- **보류한 리뷰 지적이 있다.**
  - `createRandomSolution`을 크기 4 이하로 직접 호출하면 빈 배열이 나온다.
  - `json_object` 모드에서 코드 펜스가 붙은 응답은 처리하지 않는다.
  - `play-store`의 `cycle`은 범위 밖 좌표에도 이동 수를 1 늘린다.
  - 완성한 뒤에도 "정답 보기" 버튼이 눌린다.
  - 모두 현재 호출 경로에서는 발생하지 않는다.
- **원격 저장소가 없다.** 태그 `4.0.1`~`4.2.0`은 로컬에만 있다.
