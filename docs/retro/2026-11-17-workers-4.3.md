## 운영 구성
- 총괄은 `ps-opus`이고 구현 워커는 `ps-ds`(OpenCode), `ps-sol`(Codex), `ps-hf`(OpenCode)이다. 리뷰 전용은 `ps-astra`(Codex)와 `ps-fable`(Claude)이다. 모델 약칭 매핑은 지시 파일 `ds5.md` 기준이다.
- 작업은 버전 단위로 나눴다. 4.2.2는 ps-ds 단독, 4.3.0은 Workers(ps-sol)·base URL(ps-ds)·문서(ps-hf) 분담, 4.3.1은 Select(ps-ds)·오류 노출·타임아웃(ps-sol)·문서(ps-hf) 분담이다.
- 지시는 `/tmp/ps-prompts/<워커>.md`에 quoted heredoc으로 쓰고 `herdr agent prompt`로 보냈다. 대기는 `worker-watcher` 서브에이전트가 맡았다.
- 4.3.0은 ps-astra 리뷰(`/tmp/astra-workers.md`) 전에 배포했고, 리뷰 결과를 4.3.1에서 반영했다. 이번 세션에는 전역 스킬 `ui-select`가 새로 생겼다.

## 잘된 점
- **공개 저장소·운영 URL까지 하루에 올렸다.** 4.2.1에서 저장소를 열고 4.3.0에서 Workers로 배포했다. 테스트 145~150개·typecheck·build는 매 릴리스마다 통과했다.
- **사후 리뷰가 실제 blocker를 잡았다.** ps-astra 리뷰가 공급자 오류 원문(`error.message`)이 Problem Details 응답과 console logger 양쪽으로 그대로 전달되는 경로를 가짜 키로 재현했다. 4.3.1에서 외부 응답을 일반화된 문구로 바꾸고 취소 신호와 60초 타임아웃을 `AbortSignal.any`로 합성했다(현재 `src/infra/openai.ts`에서 확인).
- **비밀값 취급 절차를 지켰다.** `.env`에서 앱 키만 골라 0600 임시 JSON으로 `wrangler secret bulk`에 올리고 파일을 삭제했다. `DISCORD_WEBHOOK_URL`은 올리지 않았다. 리뷰에서도 Authorization 헤더나 env 객체를 직접 로깅하는 코드는 없었다.
- **중간 지시를 버전 순서로 흡수했다.** 4.3.0 작업 도중 들어온 4.2.2 요청을 별도 커밋·태그로 먼저 끼워 넣어 태그 순서와 내용이 어긋나지 않게 했다.
- **스모크를 실제 응답까지 확인했다.** `/`·`/queen`·`/chat` 200 외에 `POST /api/chat`의 실제 모델 응답을 확인했다.

## 남은 과제
- **공개 URL에 인증·rate limit이 없다.** 리뷰도 blocker로 확정하지 않았지만 공개 데모가 아니면 Cloudflare Access 또는 WAF 규칙이 필요하다. 사용자 결정이 필요하다.
- **리뷰 미결 항목.** R1 기본 info 로그에 모델 응답 본문·도구 인자 전체 기록(비밀값 제거 테스트 없음), R3 요청 abort 시 NDJSON 스트림 미종료·chat 취소 upstream 미전파, R4 function 모드의 `strict: true`·`reasoning_effort: 'none'` 고정(Groq gpt-oss 등과 비호환). R4는 `docs/providers.md` 미결에 기록돼 있다.
- **라벨·워커 열기·릴리스·배포 스크립트가 없다.** 이번 세션 수작업 7종을 ps-ds(`scripts/herdr-*.sh`)와 ps-sol(`scripts/release.mjs`·`deploy.mjs`·`smoke.mjs`)이 만들고 있다. 완료 후 `docs/harness/operations.md`에 사용법을 적어야 한다.
- **Select 시각 확인이 끝나지 않았다.** 4.3.1의 lucide ChevronDown은 테스트로만 확인했다.
- **세션 한정 effort는 재시작 시 사라진다.** 워커 재시작 후 effort를 다시 확인하는 절차가 없다.
- **ai-ps 전용 Discord 채널 미정.**
